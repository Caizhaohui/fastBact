## The Problem
In commit `37a7c0b` (Phase F7), external neighbors of committed paths were inserted into `rejected_nodes` (`exspander.rs:997`) to protect them from Stage 5 orphan cleanup.
However, `find_candidate_paths` at line 246 checks:
```rust
if u_node.is_deleted || u_node.is_circular || rejected_nodes.contains(&u.id()) {
    continue;
}
```
This causes any external neighbor $X$ of an earlier committed path to be silently skipped in candidate search for subsequent seeds!
Furthermore, Claude Opus 5.5's deep review proved:
1. Codex Option A (two sets, still checking `rejected_nodes` in BFS) is INSUFFICIENT because older writers (fork decision failures, validation rollbacks) still insert into `rejected_nodes`, causing cross-seed pollution (CE-2 / Test J).
2. Option C (simply removing `rejected_nodes` from BFS) has a latent flaw: when a node was consumed by an earlier seed, BFS skips it at `is_deleted`, allowing a weak decoy candidate $D$ on an alternate exit to win under the single-candidate rule ($W/C \ge 0.05$) when the true biological continuation was the consumed node (CE-3 / Risk R-2).
3. The selected solution is **Refined Option D**:
   - Decouple `cleanup_protected_nodes` completely from candidate search (remove from `find_candidate_paths`).
   - Track `consumed_nodes: HashSet<u32>` resolver-wide.
   - Traverse consumed nodes in BFS as shadow candidates (`through_consumed: true`). Shadow candidates are NEVER spliced.
   - At decision sites, if a shadow candidate on an alternate exit has strong evidence (`best.total_weight < threshold * shadow.total_weight`), block the decision and preserve the fork!
